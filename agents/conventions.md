# Key conventions: the long form

The full text of each convention, with the incident that established it. CLAUDE.md keeps a one-to-two-line version of each.


- Never allocate from the managed heap inside smash internals — use BootstrapAlloc
- `BootstrapAlloc`'s allocation path is lock-free by design: regions are mapped read/write up front (`vm::mapPagesNoReserve`, `MAP_NORESERVE` so untouched pages still cost nothing) and `tryAllocFrom()` is a pure CAS bump. `expand_lock_` guards `addRegion()` alone. **Never take that lock from the allocation path**: `expandAndAllocate()` already holds it when it calls `tryAllocFrom()`, so re-entering it self-deadlocks on a non-recursive spinlock and wedges every other thread behind the holder. That is exactly what the old `ensureCommitted()` did — it `mprotect`-ed the next pages under `expand_lock_` on every allocation that crossed a page — and it hung the process the first time the arena had to grow. Trigger is total allocation, not concurrency: a `ThreadCache` is 92 KiB and goes through `allocate()`, so ~728 of them exhaust the 64 MiB initial region, and 4 threads were enough to reach it.
- Data pages never contain metadata (bitmap-based free tracking, pointer arrays in thread cache)
- Fine-grained locking: per-slab spinlocks, per-page spinlocks. No global heap lock. 4 arenas reduce slab lock contention.
- `PageLockTable::tryLock()` used for prefetch to avoid deadlock
- NUMA-bound blocks (`malloc_numa` → `LargeAlloc::allocateOnNode` → `VmRegion::allocatePagesOnNode`) live in per-node arenas inside the VmRegion and are compressed like any other page.
  - **Growth:** an arena grows in 64 MiB grid-aligned chunks carved off the shared bump pointer, and each chunk is `mbind`-ed once.
  - **No fixed per-node slices:** the compressor walks `[0, committedPages())` page by page every tick (chunk-bitmap rebuild, deferred-madvise sweep, soft-dirty pagemap read). Slices above the shared heap would stretch that walk across the whole region.
  - **Freeing:** freed node pages must go back to their own arena, never the shared free lists, or the binding leaks into ordinary allocations.
  - **Remaps:** any `MAP_FIXED` over a node page drops its policy. `remapPages()` calls `vm::g_after_remap_hook` to bind it again; a new `MAP_FIXED` site must do the same.
- Compressed blobs: a worker stores through `workerStore(worker)` (its node's store, or the shared one) and releases through `storeOfBlob(page_idx)`, which reads the `blob_node_` byte recorded at store time. That lookup is a **performance** hint only — `CompressStore::release` routes by the region's recorded `owner`, so a release arriving at the wrong store is forwarded instead of resetting that region under the wrong shard lock while its own shard bumps into it (it then locks the shard the region records, `Region::shard`, never one derived from the page index). Keep it that way: an ordinary heap page migrates between nodes, so the owning store can never be derived from where the page lives now, and a wrong guess must stay harmless. A blob in a node store never spills to the file-backed store (`blobIsNodeLocal`).
- A repeated free is only visible in two places, and the obvious one is the wrong one. `free(p); free(p);` never reaches the slab bitmap — both pointers land in the `ThreadCache` lane — so lane-scanning is what catches the common case, and the bitmap check (`Span::deallocate`, 1 = free) catches only what survives a drain. Any future hardening that inspects just one of the two will silently miss half the cases. Whatever detects it must **drop** the second free rather than apply it, or `--allocated_count` underflows and corrupts `Slab::deallocateOne`'s list transitions.
- Never export both `name@@VER` and `name@VER` from libsmash for the same interposed function. A versioned reference resolves to the exact-version match — the `@` alias — and if that alias is a thin `jmp name@plt` forwarder, the GOT slot points back at it: a jump to itself that spins at 100% CPU. List only the `_NN` alias in the version script and let the bare name fall under `local: *`. See "_FORTIFY_SOURCE and the `__*_chk` aliases" in [agents/syscall-compat.md](syscall-compat.md).
- The generated version script must be a declared `LINK_DEPENDS` of the `smash` and `smash_noopt` targets. CMake infers no link dependency from a `--version-script=` linker flag, so without it a change to `smash_version_script.map.in` regenerates the map and relinks **nothing** — and the next test run silently measures the previous library. (`configure_file` only rewrites the generated map when its content changes, so `touch`ing the `.in` correctly does nothing.)
- Thread hooks must be exported at the version the caller binds. `pthread_create`/`pthread_exit` are exported **twice** — at the base version and at `GLIBC_2.34` (`.symver` aliases in `linux_syscall_wrappers.cpp`, both names listed in the version script). glibc 2.34 merged libpthread into libc and made `GLIBC_2.34` the default for these, so a base-only export means alloc8's interposer never sees an application thread and every thread leaks its 92 KiB `ThreadCache`. The same rule as for versioned syscall wrappers (see [agents/syscall-compat.md](syscall-compat.md)); it applies to thread hooks too, and it failed silently for both.
- A thread cache must be reclaimable without the interposer. `getOrCreateThreadCache()` arms a `pthread_key_t` whose destructor drains and pools the cache on any thread exit, however the thread was created; `threadCleanup()` clears that key's value so a wrapped thread cannot return the same cache twice, and the destructor re-checks `currentThreadCache()` before acting. Keep both guards if you touch either path.
- `newThreadCache()` returns nullptr when BootstrapAlloc is exhausted, and every `getOrCreateThreadCache()` caller handles it: `mallocSlow` falls back to the system allocator, and both `freeSlow` paths return the object straight to its slab via `Slab::deallocate(span, ptr)` rather than dropping it.
- Every file-scope `extern thread_local` must be declared **and** defined `constinit`. Without it the compiler treats the variable as possibly dynamically initialized and guards each read with a `cmpq`/`je`/`call` on its `_ZTH...` init wrapper — on the malloc and free fast paths — and that guard also feeds a GCC `-fsanitize=null` bug that reports a spurious null load over correct code (see "Sanitizers" in [sanitizers.md](sanitizers.md)). `constinit` is a compile-time assertion, so a non-constant initializer fails the build rather than silently reinstating the guard.
- A thread that parks on a futex must check its exit flag **before** parking, not only after it observes a work-generation change. The publisher sets the flag, bumps the generation and wakes, in that order; a thread whose first instructions run after all three has nothing left to observe and sleeps forever, taking the joiner down with it. Re-checking after a generation change is not enough, because a thread that starts late never sees one. This cost a 2.3% hang of short-lived processes (see "Compressor shutdown race" in [defect-history.md](defect-history.md)).
- Never trust an idle-bitmap mark you have not read back, and never read the idle bit of a page you did not mark. The kernel silently drops marks on pages not on the LRU (the zero page, freshly faulted pages), and an unmarked page reads "not idle", which the read-detection code interprets as "read". Either mistake keeps pages hot forever, and only as root — see "Idle-page read tracking" in [defect-history.md](defect-history.md).
- Never give a smash thread a fixed stack size. glibc puts the application's static TLS and the guard page inside every thread's stack, so a fixed 128 KiB made **all** of smash's threads fail with EINVAL once an app carried ~128 KiB of static TLS — "`pthread_create(coordinator) failed; compression disabled`", and smash silently ran as a plain allocator. Use `createSmashThread()` / `smashThreadStackSize()` (`util/thread_stack.h`), which add glibc's minimum (`__pthread_get_minstack`) and round to the *runtime* page size, and fall back to default attributes if still refused. Guarded by `test_static_tls_threads_{full,large_only}` (512 KiB of static TLS; a cold block must leave RSS — with the old stacks it stayed 100% resident). A thread count is not a valid check: on a multi-node host the NUMA workers, with 1 MiB stacks, started while the coordinator did not.
- Never make a shared free list lock-free unless it is ABA-safe. The span-descriptor list was a Treiber stack whose pop read `s->next_free` and then CASed the head; under many threads it installed a descriptor that was in use, smash then failed to recognise its own block on free and forwarded it to glibc (`free(): invalid pointer`) or the process segfaulted. It hit every multithreaded program doing concurrent `LargeAlloc` traffic — aligned allocations in full mode, allocations over 16 KiB in large-only mode, the production configuration. Measured with a 64-thread stress: 5/5 runs crashed; the current code with only that list reverted to the Treiber stack, 5/5; with a spinlock stack, 0/5. `test_span_descriptor_race_{full,large_only}` guard it (probabilistic: the old stack crashed about 2 runs in 3). A span is created far less often than an object, so a spinlock costs nothing measurable here.
- Never return empty slab spans to the arena on every free. It looks like hygiene and costs ~70 % on mi-stress: spans that oscillate between empty and in use pay a release, a decommit and zero-fill faults every round trip. Empties are free to keep until the arena runs out; the VmRegion exhausted hook is the place to reclaim them (see "Small allocations after the arena is exhausted" in [defect-history.md](defect-history.md)). Anything that runs inside that hook may hold a slab lock already, so it must take other slab locks with `tryLock` only, and must never call `allocatePages()`.
- A smash thread must never be what keeps a process alive. glibc ends a process when its thread count hits zero, so any thread smash creates has to register with `exit_guard::ThreadRegistration` (`util/exit_guard.h`) and be stopped by `SmashHeap::stopAllSmashThreads()`. A new background thread that skips either one re-introduces the `pthread_exit()`-from-main hang, and does so silently — the process just never exits. Any stop path must also skip joining the calling thread.
- Compressor startup: constructor at priority 201 (after alloc8 pthread hooks at 200) calls `xxthread_init()` twice on macOS, once on Linux, ensuring the compressor starts even for non-ObjC programs (e.g., Python) and single-threaded programs
- Fault handler handles ACTIVE state (not just ACTIVE_MONITORING) to cover the race where Phase 3's batched mprotect overwrites a per-page PROT_RW restoration
- ThreadCache `drain()`/`drainAll()` bucket pointers by `span->arena_id` before returning to correct arena's slab
- Never put a page into the shared free map, a sub-arena's free runs with its dirty bit clear, or the chunk pool unless it is fresh (never handed out) or went through `decommitPages()` first. `calloc` does not clear a large block whose pages read as zero already: `VmRegion::allocateLargePages` reports `zeroed` for every run from those places, and only a block with a page marked dirty (`takeFromSubLocked`, which `PageRunMap` tells how many it took) or a run-cache hit says otherwise, through `took_dirty` or `LargeAlloc::allocate`. `vm::decommitZeroes()` turns it all off when the decommit keeps the bytes (`SMASH_MADV_FREE=1`, `SMASH_NO_DECOMMIT=1`, macOS). Every path in 2026-10 goes through `releasePages`/`releasePagesNow` (decommit, then insert) or carves fresh pages; a new one that inserts dirty pages anywhere else makes `calloc` return the last block's bytes. Before 2026-10-28 every `calloc` wrote its whole block (alloc8's wrapper), which cost 0.7 s and 960 MiB of RSS for `calloc(1 GiB)`. Guarded by `test_calloc_*` ([tests.md](tests.md)).
- Fresh region goes last. Every miss drains what is on its way back before it takes fresh pages (`VmRegion::allocatePages` once, `allocateOnSubArena` for up to `kCarveWaitMs` over the queue and the purges in flight, `allocateBigOnSubArenas` already did). The bump pointer never comes down, and every tick's bitmap, the idle scan and the resident metadata follow it. `smash_sim` with 512 MiB live and a 200 us madvise walked all of a 64 GiB arena in 8 s with the fresh pages taken first, and 1.4-2.9 GiB with the drain; `test_smash_sim_walk_*`.
- A sub-arena's free runs hold dirty and clean pages side by side. Kept as two owners they could not merge, a chunk of nothing but free pages served no request longer than its longest run of one kind, and only a full region looked across them. Whatever a new path does with such a run, the dirty bits of pages out of the map are the caller's (`removeRunUnlocked` leaves them, `markDirtyUnlocked` needs them clear), and a page handed out must have its bit clear (the takes do that). Only a wholly clean run covering a chunk goes to the pool.
- Under `SMASH_THP_UNIT` a unit compressed whole (`kUnitWhole`) comes back whole or not at all. One 4 KiB written through `/proc/self/mem` into a dropped huge range makes the kernel allocate the whole 2 MiB, mostly zeros that stay resident under pages still marked compressed; that is why prefetch skips a unit's pages and every restore of one goes through `restoreUnit`. Any call that protects or drops a unit covers all 2 MiB: over part of a PMD, `mprotect` and `madvise` split the huge mapping, which is what the option exists to avoid. `restoreUnit` takes the unit's 512 page locks in ascending order with none held; everything else that holds several page locks takes them with `tryLock` (Phase B, `restoreGroup`, prefetch, `makeReadableForSnapshot`) or in ascending order (`escalateBatch`), so the order is safe. A free clears the marks of the units it touches after releasing its pages, and `compressUnit` checks its pages again after marking, so a free racing the mark cannot leave one on pages that are gone; a stale mark is dropped by the next Phase B that meets the unit.
- `PageRunMap::take` and friends stop after `kTakeScan` runs of the request's own bin, so a miss does not prove nothing fits. Anything that fails or leaves the arena on a miss must use `takeAny` / `kScanAll`.
- An application's `sigaction()`/`signal()` for SIGSEGV or SIGBUS must never displace smash's handler. They are interposed (`linux_syscall_wrappers.cpp`) and routed to `FaultHandler::interposedSigaction`, which records the application's handler as the one to chain to and leaves smash's in the kernel; queries return the application's handler. smash's own installs and restores must go through `FaultHandler::sysSigaction` (libc's real `sigaction`), since a plain call from inside libsmash lands in the wrapper. The chained handler is a seqlock written by application threads while the signal handler reads it: a writer must copy the caller's structs **before** taking the lock (they are application memory and may fault into smash). Dispatch decides `SIG_DFL`/`SIG_IGN` by the handler value, not by `SA_SIGINFO`, and applies the handler's `sa_mask` and `SA_RESETHAND` as the kernel would. The compressor's periodic re-claim stays as the backstop for the raw `rt_sigaction` syscall. Before this, an application's handler held SIGSEGV until the next compressor tick (0.3-3 s), and every fault smash had to resolve in that window reached it as a crash — see [defect-history.md](defect-history.md).
- In the default deferred mode the compression snapshot reads the page through `/proc/self/mem` and leaves its protection alone; the shadow page is then made PROT_READ in a batch (`flushShadowReadable`). Shadow pages must stay readable (`test_prefetch`), and writes to them fault into the COMPRESSED_SHADOW handler case. Never protect pages one `mprotect` at a time in a compressor phase: on a 128-core box each call is a TLB shootdown to every core, and per-page calls in phases 2 and 3 made ticks take minutes (`test_phase3_batch` counts them).
- At `vm.max_map_count` a fault restores the page's run or its whole VMA, never waits for a VMA. Making one page of a PROT_NONE run accessible splits its mapping (+2 VMAs), which fails with ENOMEM at the cap; changing a whole VMA's protection needs no split. Near the cap (`SMASH_VMA_MARGIN`, by the shared estimate) the fault restores the page's run up to its nearer end (`restoreNearCap`), at the cap the whole VMA (`restoreWholeVma`: the run from page states first, `/proc/self/maps` only if that needed a split — the read costs ~0.3 s at a 1M-map cap). If a page of the range is busy, mid-compression, free or in a whole unit, nothing changes: the faulting page keeps its state, its blob and its deferred-madvise bit, the lock is released, and the access re-faults (`capStall`: yield, then 1 ms sleeps; FATAL after 2 s without progress). Incidents: the first version spun silently and marked the page ACTIVE without its data; the second waited for a VMA under the page lock and aborted after 2 s, which at the cap was every time (upstream `test_vma_cap` with no prefetch). Never back up a failed `mprotect` of a page holding live data (ACTIVE, watched) with `remapPages`: at the cap it fails too, and wherever it succeeds it maps zeros over the page.
