# Configuration: constants and environment variables

Full reference, moved from CLAUDE.md.

Key constants in `include/smash/config.h`:
- `kColdTicks = 2`: Ticks without access before fast-tier compression considered
- `kVeryColdTicks = 60`: Cold-tick threshold for the deep-tier (zstd-9) profile in the ROI model
- `kMinCompressRatio = 0.75`: Only store if compressed < 75% of original
- `kPrefetchWindow = 2`: Pages prefetched in each direction on fault
- `kDictTrainSamples = 0`: Pages before dictionary training (disabled by default; dicts net-negative)
- `kNumArenas = 4`: Call-site arena count (must be power of 2)
- `kCompressorWorkers = 2`: Initial compression worker count
- `kMaxCompressorWorkers = 8`: Cap for adaptive worker scaling (Little's Law)
- `kCompressStoreShards = 8`: CompressStore lock shards
- `kChunkSize = 64`: Pages per chunk for scan bitmap
- `kLargeAllocVmThreshold = 1MB`: Only large allocs above this go in VmRegion

Runtime environment variables:
- `SMASH_LARGE_ONLY=1`: Large-only mode — small allocations (≤16KB) pass through to system malloc. Production-supported config for concurrent workloads
- `SMASH_DEFER_MADVISE=1`: Default ON. Defers `madvise(MADV_DONTNEED)` to a per-tick sweeper after `SMASH_DEFER_MADVISE_TICKS` quiescent ticks (default 50). Load-bearing for correctness; do not disable in production
- `SMASH_DEFER_MADVISE_TICKS=N`: Number of ticks (default 50, ≈500 ms) a page must be quiescent before sweeper madvises it
- `SMASH_MODE=compress_only`: Compress-only mode — track pages without replacing malloc
- `SMASH_TRACK_EXTERNAL=1`: Register application-direct `mmap` / `mach_vm_allocate` results so the compressor sees them. Opt-in (see [external-tracking.md](external-tracking.md))
- `SMASH_DEFER_PHASES_MS=N`: Skip Phase 2 (compress) + Phase 3 (monitor) for the first N ms after start. Useful for workloads that establish IPC channels at startup with buffers in smash-managed pages (Firefox sweet spot is 30000)
- `SMASH_WRITE_TRACK=auto|softdirty|uffd|none`: How writes are detected (default `auto`, chosen by testing each mechanism; see "Write tracking" in [defect-history.md](defect-history.md)). `SMASH_SOFTDIRTY=0` still selects Phase 3 PROT_READ monitoring. When `auto` (or an explicit `softdirty`/`uffd` that fails) ends at `none` — arm64 before Linux 6.7, which has neither soft-dirty nor async userfaultfd write-protect — smash prints a `[smash WARN]` saying so; an explicit `none` is quiet. Measured on a 6.6 arm64 kernel: `track=none` with 103 of 144 GiB of the arena active and uncompressed
- `SMASH_PROTECT_CHUNK_PAGES=N`: pages per Phase 3 arming run, and so per `mprotect` (default 256, clamped to [1, 256]). Each contiguous stretch of a run is armed with one call
- `SMASH_STATS_SIGNAL=1` also prints a `[smash pipeline]` line after the stats line: compressor ticks and the last/slowest tick in ms, ticks deferred by the VMA guard; phase 1 page-ticks accessed vs idle; phase 2 pages at the cold floor, escalated to read watching, eligible, routed to a node group, skipped by a budget/profile hint; compression attempts, blobs stored, ratio-gate failures; shadow pages checked, released, found changed, and reclaim stops at the VMA cap; faults on monitored, shadow, compressed and ACTIVE pages; the wall time of each phase of the last tick (`phase_ms=1/2/3/4`) and the slowest so far (`max=`); Phase 1's minor faults on compressor threads, slowest single range, the worker count of the last tick and the CPU-pressure cap last computed (`cap=`, 0 = none); Phase 3 pages armed and `mprotect` calls; Phase 2 `mprotect` calls; re-arm backoff (`rearm hot=` write faults on watched pages within a tick of arming, `waits=` page-ticks left unarmed); write-fault locality (`group nbr_active=`: summed over write faults, other pages of the faulting page's aligned 16-page group already ACTIVE) and `restored=` (neighbours a group restore made writable); phase 5 (node groups draining their queues, where most compression runs on a multi-node host) last and slowest wall time (`p5 ms= max=`). Cumulative since start. A second line, `[smash phase time] thread ms usr/sys/runq/blocked: p1=… p5=…`, splits each phase's thread time, summed over every thread that ran it: user CPU, kernel CPU (`getrusage(RUSAGE_THREAD)`), runnable but waiting for a CPU (`/proc/thread-self/schedstat`), and the wall time left over (blocked on a lock such as `mmap_lock`, a futex or I/O). The same line ends with `tick ms total= phases=` (all tick time and the part spent in phases 1-5, cumulative) and the coordinator's cumulative ms in each step outside the phases: `efficiency` (budget recompute), `vma_sync` (re-reading `/proc/self/maps`), `bitmap`, `node_chunks`, `adapt` (worker count), `dict` (dictionary training), `sweep` (deferred madvise). Added when a 97 s tick showed phases summing to ~22 s (it was a dump mixing two ticks: the next run had 99% of tick time in the phases). Then `syscall ms memread= (N calls) p2_mprotect= p3_mprotect= p4_release=`: wall ms inside phase 2's `/proc/self/mem` page snapshots (two per page with FixAv: snapshot and verify), its `mprotect` calls, phase 3's arming, and phase 4's release and look-ahead arming — which calls the `blocked` column waits in. Sampled only with `SMASH_STATS_SIGNAL=1`. Checked on 8 CPUs with 16 busy-loop hogs: phase 5's runq went from 167 to 3284 ms. Added to find where pages stop when an application kept 115 GiB watched and compressed nothing
- `SMASH_NO_SIGACTION_WRAP=1`: the application's `sigaction()`/`signal()` for SIGSEGV/SIGBUS go to libc untouched again, so its handler replaces smash's until the next compressor tick re-claims it (the behaviour before the interposition; for measuring it)
- `SMASH_SIGTRACE=1`: one line per fault smash does not resolve and passes on (`[smash sig] ... chain_kind=...`), with what smash thinks the address is (arena page and its state, or not smash's). The record to ask for when an application with its own SIGSEGV handler crashes: that handler runs instead of smash's `[smash FATAL]` line
- `SMASH_DUMP_CRASH_BT=1`: backtrace before the process dies, only when the fault chains to the default action (no application handler)
- `SMASH_WRITE_TRACK_SIMULATE_OLD_KERNEL=1`: tests only — the soft-dirty and userfaultfd probes report unavailable, as on arm64 before 6.7
- `SMASH_CPU_PRESSURE_CAP=0`: disable the compressor's CPU-pressure cap (workers then follow the Little's-law estimate alone, up to `kMaxCompressorWorkers`). The cap is `max(floor, nproc - round(1-min loadavg))`, floor `clamp(nproc/16, 2, kMaxCompressorWorkers)` on >= 4 CPUs, else 1. It used to subtract every thread of the process, so a process with nproc threads or more always got one worker (`test_worker_cap`).
- `SMASH_TEST_TICK_DELAY_MS=N`: test-only; the compressor sleeps N ms at the end of every tick, to reproduce the multi-minute ticks of a large contended host (`test_slow_tick`). Cold counts, shadow ages and re-arm waits advance by the tick's length in nominal `kCompressIntervalMs` ticks (at least 1, cold counts saturating at 255 and stopping at the cold floor so the read-watch tick still happens), so `SMASH_COLD_TIMEOUT_SEC` and `SMASH_DEFERRED_RECLAIM_DELAY` mean seconds even when ticks do not.
- `SMASH_REARM_BACKOFF_MAX=N` (default 6, 0 = off, max 7): under page-protection write tracking, a page written within a tick of being armed waits 2^exp ticks before Phase 3 arms it again, exp rising by one per such fault up to N (6 = 64 ticks) and cleared by a fault after 8 quiet ticks. Bounds each hot page to one write fault (SIGSEGV + `mprotect`) per 2^N ticks instead of one per tick; costs a page that turns cold after being hot up to 2^N ticks more before it is compressed. 2 bytes per page of metadata. See performance.md, "Hot pages were re-armed every tick".
- `SMASH_RESTORE_GRANULE_PAGES=N` (default 1 = off; power of two up to 512): under page-protection write tracking, a write fault on a watched page makes its whole aligned N-page group writable, one `mprotect` per contiguous stretch of ACTIVE / ACTIVE_MONITORING pages (compressed, shadow and free neighbours are never touched; neighbours are taken with `tryLock` only). Writes that cluster then cost one fault per group: 1.05 -> 0.062 faults per page per tick for a sequential writer at N=16. Neighbours made writable are re-armed by the next Phase 3 (they do not inherit the faulting page's backoff) and their cold count is frozen for that tick (neither counted idle nor reset). Scattered writes gain nothing and pay extra re-arming: a random-write stress had 14.8k -> 12.4k faults for 185k neighbours restored. Decide from `group nbr_active=` / `faults monitor=` with it off: the average number of already-written pages in a faulting page's 16-page group.
- `SMASH_WATCH_GROUP_PAGES=G` (default 1 = off; power of two up to 64): coarse watching. An aligned group of G pages is idle only when all of its pages are — Phase 1 gives every uncompressed page of a group the group's lowest cold count — so a group is armed, escalated, compressed and released in the same tick, a write fault restores the whole group (implies `SMASH_RESTORE_GRANULE_PAGES` >= G), a fault on a compressed page prefetches the rest of its group (across a block boundary too), and a group is not armed while one of its pages waits out a re-arm backoff. Pages are still compressed 4 KiB at a time, so fault latency is unchanged; the cost is that one hot page keeps its whole group uncompressed. 64 MiB written in random page order under `SMASH_SOFTDIRTY=0`: at most 9445 mappings and 40880 protection calls per page, 678 and 11141 with G=16 (`test_watch_group`). Worker ranges and node-group slices are cut on 64-page boundaries when it is on.
- `SMASH_NO_MONITOR=1`: Disable Phase 3 (PROT_READ access tracking) entirely. Trades cold-detection accuracy for compatibility with code paths that synchronously check page protection
- `SMASH_VM_GIB=N`: Size of the compressible arena, default 16, ceiling 1 TiB (`kVmMaxBytes`). The arena is a PROT_NONE `MAP_NORESERVE` reservation and its per-page metadata is demand-paged, so an unused arena costs address space, not memory (measured: 16, 64 and 1024 GiB all start at 23.3 MB RSS). If the reservation fails — a 39-bit-VA arm64 kernel, `ulimit -v` — `VmRegion::init` halves the request down to 256 MiB and says so, instead of silently running without compression as it used to (measured: with a 48 GiB address-space limit, `SMASH_VM_GIB=1024` gets a 32 GiB arena and compresses; before, compression was off). The old 64 GiB ceiling was an estimate of metadata cost, not a limit; page indices are 32-bit, so the hard bound is 16 TiB
- `SMASH_NO_DRAIN_WAIT=1`: an allocation that finds no free run gives up immediately instead of waiting for runs that are freed but still queued for decommit (the pre-fix behaviour). For measuring what that wait is worth on a given machine — an absolute fallback rate is not portable across core counts
- `SMASH_NO_RECLAIM_WAIT=1`: every thread that runs the arena out runs its own empty-span reclaim pass concurrently and treats a slab another pass holds as empty, instead of waiting for that pass (the pre-fix behaviour). For measuring the wait; see `test_arena_reclaim_concurrent` in [tests.md](tests.md).
- `SMASH_RUN_CACHE_MIB=N`: per-CPU cache of freed large runs, N MiB per CPU (256 shards, one per CPU up to 256 CPUs; 8 runs each; runs over 64 MiB never cached); 0/unset = off (default). A block freed warm (no page compressed) is parked and reused by the next same-size allocation on that CPU and node, skipping the node arena's lock, the free map, the decommit queue, mprotect/madvise and zero-fill faults. Costs up to (CPUs in use) x N MiB of resident memory while runs are parked — 128 CPUs at N=32 is 4 GiB. See [design-run-cache.md](design-run-cache.md)
- `SMASH_RUN_CACHE_AGE_MS=N`: age after which the decommit thread returns a cached run to the arena (default 50)
- `SMASH_SUBARENAS=1`: per-CPU sub-arenas for the NUMA node arenas (`malloc_numa`) and for plain `malloc`'s large blocks (the shared arena, unbound chunks), off by default ([design-subarenas.md](design-subarenas.md)). Each node's chunks are owned by sub-arenas with their own lock; a block freed warm goes back to its chunk's sub-arena as **dirty** — resident, no syscall — and any later allocation that fits reuses it without zero-fill faults. Compressed frees still go through the decommit queue and come back **clean**. Turns the run cache off. Costs resident memory up to `SMASH_DIRTY_MAX_MIB` per sub-arena for up to `SMASH_DIRTY_DECAY_MS`; `smash_subarena_info()` reports the dirty bytes
- `SMASH_SUBARENAS_PER_NODE=N`: sub-arenas per node, 1..64 (default: one per CPU of the node, from sysfs). A thread uses its CPU's rank within the node; a CPU of another node maps by `cpu % N`. The shared arena's set gets a slice of N per node with CPUs, scaled down to 64 in total (128 CPUs over 4 nodes: 16 per node), so CPUs of one node share sub-arenas with each other only
- `SMASH_DIRTY_DECAY_MS=N`: age at which the node's decommit thread (sweeping every 50 ms, trylock only) returns a dirty run to the OS (default 1000; 0 = next sweep)
- `SMASH_PURGE_EPOCH_MS=N`: how often each set's purger sweeps for dirty runs past the decay time (default 50). A free over the cap never waits for it. The sub-arena tests set 200 so a purge that did wait would miss their 20 ms window
- `SMASH_DIRTY_MAX_MIB=N`: dirty MiB per sub-arena before the oldest are purged early, splitting the run that crosses the cap (default 256). A free that crosses it wakes the purger at once (its loop polls every 100 µs), so the bound holds within milliseconds, not only at the 50 ms sweep
- `SMASH_ALIGN_SLOT_SEARCH=1`: Keep an aligned small allocation in its natural size class and search that class's bitmap for an aligned slot, instead of promoting it to a class that is a multiple of the alignment. **Off by default and usually a loss** — the stranded slots make it up to 7× worse, and call-site arena routing keeps plain allocations from filling them. See "Aligned small allocations come from the slab" in [allocation-paths.md](allocation-paths.md)
- `SMASH_ALIGN_SLAB=0`: Restore the old aligned-allocation routing, where any alignment above 16 B goes to `LargeAlloc` and costs a whole page per object. Default ON (slab-served); see "Aligned small allocations come from the slab" in [allocation-paths.md](allocation-paths.md)
- `SMASH_MID_BINS=1`: Serve the (16 KiB, 1 MiB) band from size-binned chunks in the compressible arena instead of one direct `mmap` each. Off by default: it trades ~10% of the requested bytes to size-class rounding for compressibility and much cheaper churn, which only pays for blocks that go cold. See "Mid-size bins" in [allocation-paths.md](allocation-paths.md)
- `SMASH_THP=1`: `madvise(MADV_HUGEPAGE)` the arena. Off by default: it keeps a dense hot set on huge pages (TLB coverage) while the cold set still compresses, but inflates RSS 22× on a sparse touch pattern. See "Hugepages and THP" in [allocation-paths.md](allocation-paths.md)
- `SMASH_LARGE_ALLOC_VM_THRESHOLD=N`: Bytes at or above which a large allocation is placed in the compressible VmRegion instead of a direct mapping (default `kLargeAllocVmThreshold` = 1 MiB; rounded up to a page). **This decides what can be compressed at all** — a block below it is never walked by the compressor and stays resident however cold it gets. Lower it for a workload whose footprint is mid-sized blocks; see "Which allocation sizes are actually compressed" in [allocation-paths.md](allocation-paths.md)
- `SMASH_COLD_TIMEOUT_SEC=N`: Override cold timeout at runtime
- `SMASH_DOUBLE_FREE=off|warn|abort`: Double-free detection, **default `off`**. `warn` reports to stderr (rate-limited, via `safe_snprintf` + `write(2)` — never `fprintf`, which can call malloc and reenter) and drops the second free; `abort` reports then traps. A double free is UB, so this is a debugging aid rather than a safety guarantee: it is not a promise that a detected double free was harmless, only that this one was dropped. No measurable cost when enabled (see `test_double_free_full`)
- `SMASH_NO_EXIT_GUARD=1`: Disable the process-exit guard, so smash's background threads keep the process alive after the application's last thread exits (the pre-fix behaviour — see "Process exit after `pthread_exit()` from main" in [defect-history.md](defect-history.md)). Escape hatch for an application that genuinely relies on a library's threads outliving its own
- `SMASH_COOLING_CLOSE_TICKS=N`: Cooling-page closing threshold (default `getColdTicks()/2`; `0` disables). Slab allocation prefers warm/EMPTY pages over pages whose cold streak ≥ N, and redirects to a decommitted empty span (never a new one) when the front span has only cooling/compressed free slots. Allocator-induced re-heats are counted in the `reheat=` field of the SIGUSR2 stats line (`SMASH_STATS_SIGNAL=1`); the telemetry threshold stays at the default even when closing is disabled, so A/B runs can measure prevented re-heats. Note: objects recycled through the thread cache bypass slab placement entirely — the app's writes into recycled objects re-heat their pages regardless of this policy
- `SMASH_VERY_COLD_TICKS=N`: Override deep-tier cold-tick threshold (ROI model). `9999` disables the deep tier entirely (fast tier only).
- `SMASH_ROI_THRESHOLD=N`: Override ROI cutoff (default 1024)
- `SMASH_FAST_COMP_MBS_HI/LO`, `SMASH_FAST_DECOMP_MBS_HI/LO`: Override fast-tier calibration
- `SMASH_DEEP_COMP_MBS_HI/LO`, `SMASH_DEEP_DECOMP_MBS_HI/LO`: Override deep-tier calibration
- `SMASH_CALIBRATE=always|never`: Force/skip startup calibration
- `SMASH_CALIBRATION_FILE=path`: Cache and reload calibration
- `SMASH_NUMA_COMPRESSOR=0`: Disable the per-node compressor groups. `malloc_numa` pages are then compressed by the default workers into the shared store
- `SMASH_NUMA_WORKERS=N`: Threads per node compressor group (default `kCompressorWorkers`, capped by the node's CPU count and 8)
