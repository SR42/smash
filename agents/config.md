# Configuration: constants and environment variables

Full reference, moved from CLAUDE.md.

Key constants in `include/smash/config.h`:
- `kColdTicks = 2`: Ticks without access before fast-tier compression considered
- `kVeryColdTicks = 60`: Cold-tick threshold for the deep-tier (zstd-9) profile in the ROI model
- `kMinCompressRatio = 0.75`: Only store if compressed < 75% of original
- `kPrefetchWindow = 2`: Pages prefetched in each direction on fault; the default for `SMASH_PREFETCH_WINDOW`
- `kDictTrainSamples = 0`: Pages before dictionary training (disabled by default; dicts net-negative)
- `kNumArenas = 4`: Call-site arena count (must be power of 2)
- `kCompressorWorkers = 2`: Initial compression worker count
- `kMaxCompressorWorkers = 8`: Cap for adaptive worker scaling (Little's Law)
- `kCompressStoreShards = 8`: CompressStore lock shards
- `kChunkSize = 64`: Pages per chunk for scan bitmap
- `kLargeAllocVmThreshold = 1MB`: Only large allocs above this go in VmRegion

Runtime environment variables:
- `SMASH_LARGE_ONLY=1`: Large-only mode — small allocations (≤16KB) pass through to system malloc. Production-supported config for concurrent workloads
- `SMASH_DEFER_MADVISE=1`: Default ON. Defers `madvise(MADV_DONTNEED)` to a per-tick sweeper after `SMASH_DEFER_MADVISE_TICKS` quiescent ticks (default 50). Load-bearing for correctness; do not disable in production
- `SMASH_DEFER_MADVISE_TICKS=N`: Number of ticks (default 50, ≈500 ms) a page must be quiescent before sweeper madvises it
- `SMASH_MODE=compress_only`: Compress-only mode — track pages without replacing malloc
- `SMASH_TRACK_EXTERNAL=1`: Register application-direct `mmap` / `mach_vm_allocate` results so the compressor sees them. Opt-in (see [external-tracking.md](external-tracking.md))
- `SMASH_DEFER_PHASES_MS=N`: Skip Phase 2 (compress) + Phase 3 (monitor) for the first N ms after start. Useful for workloads that establish IPC channels at startup with buffers in smash-managed pages (Firefox sweet spot is 30000)
- `SMASH_WRITE_TRACK=auto|softdirty|uffd|none|idle|yt`: How writes are detected (default `auto`, chosen by testing each mechanism; see "Write tracking" in [defect-history.md](defect-history.md)). `SMASH_SOFTDIRTY=0` still selects Phase 3 PROT_READ monitoring. When `auto` (or an explicit `softdirty`/`uffd` that fails) ends at `none` — arm64 before Linux 6.7, which has neither soft-dirty nor async userfaultfd write-protect — smash prints a `[smash WARN]` saying so; an explicit `none` is quiet. Measured on a 6.6 arm64 kernel: `track=none` with 103 of 144 GiB of the arena active and uncompressed
- `SMASH_WRITE_TRACK=idle`: opt-in, Linux. The page_idle bitmap (`/sys/kernel/mm/page_idle/bitmap`) is the whole access signal: each scan reads whether a page's idle mark survived since the last scan (the hardware accessed bit sets on a read or a write) and marks it again, so nothing is mprotected to watch a page, Phase 3 never runs and the application takes no fault until a page is compressed; a write racing compression is caught by the snapshot verify, as with soft-dirty. Checked before `SMASH_SOFTDIRTY=0`, which it replaces. Needs real PFNs in `/proc/self/pagemap` (`CAP_SYS_ADMIN`) and the bitmap read-write (root-only by default: root, `setcap cap_dac_override,cap_sys_admin=ep` on a binary that links libsmash as a `NEEDED` entry, since a file capability disables `LD_PRELOAD`, or an ambient `CAP_SYS_ADMIN` plus a `chown` of the bitmap); otherwise it warns and uses `protread`. A huge page answers through its head PFN only, so the arena is `MADV_NOHUGEPAGE` in this mode and `SMASH_THP=1` refuses it. A page whose mark does not take (not on the LRU yet) counts as accessed, so it is never compressed early. Stats: `idle_scan=ms (N calls, P pages, W words, O other idle)` on the `syscall ms` line: W bitmap words read, O pages found idle in them that the scan did not ask about. A word read makes the kernel check all 64 of its pages and walk the mappings of each one marked idle, so O counts work done for nothing (a lower bound: a page marked idle but since accessed is walked too and reads 0). On claudepc, 1.3 other idle pages per page scanned at K=4 and 2.4 at K=1; on the 128-core arm64 box the scan cost 46 us per page over a 1800 s stress run and 86 us when idle (2026-10-19), against 0.4 us measured on x86. Each scanning thread opens the bitmap itself: sysfs runs one call at a time per open file, and a shared one serialized the workers (defect-history.md). Measured on claudepc (2-CPU x86, root), 2 GiB with 256 MiB read every 1.5 s and 256 MiB written every 2 s, 150 s: page protection with the idle read check 1.86M monitor faults, 1062 decompressions of hot pages, 37.6 s system time, read pass avg 5.3 ms / worst 41 ms; `idle` (K=4) 0 faults of any kind, 13.6 s system time, 5.4 / 12 ms; both compressed exactly the idle 393216 pages
- `SMASH_WRITE_TRACK=yt`: opt-in, Linux. The same signal as `idle` (the hardware accessed bit, reads and writes alike, nothing protected, no Phase 3), read through the youngtrace module (the `yt` tree, a separate loadable module): each request written to `/dev/youngtrace/scanner` (`pid=<self> mode=1 lo= hi=`) walks this process's page tables under `mmap_read_lock`, reports the present pages whose accessed bit is set and clears it, without a TLB flush. Needs no PFNs, no `pagemap` and no rmap walk. Checked before `SMASH_SOFTDIRTY=0`. Needs the module loaded and the device openable: the module requires `CAP_SYS_ADMIN` at `open()`, and the node is root-only (0600), so also `CAP_DAC_OVERRIDE` or a udev rule (same `setcap` + `NEEDED` arrangement as `idle`). At startup two pages of its own are written and scanned twice: they must read accessed, then not; otherwise, or when the device cannot be opened, it warns with the reason and uses `protread`. Requests cover runs of due 64 MiB slices, split at `(scan_buf_cap - 8) / 128` pages (the most a request can produce is a 120-byte record plus an 8-byte item per page, so a request is never cut by the module's buffer; `scan_buf_cap` is read from `/sys/module/youngtrace/parameters/`, 8 MiB by default, giving 256 MiB requests). A request that fails or comes back cut or unreadable counts every page it did not report on as accessed (their bits may already be cleared) and warns once. A transparent huge page is one item, so all 512 of its pages read accessed when any is, and all are marked, including those outside the request that reported it (the request clears the one bit, so the request covering the rest would read it idle): conservative, and the arena keeps the host's THP setting (no `MADV_NOHUGEPAGE`, unlike `idle`). Eight descriptors are opened at startup, one per concurrent phase-1 range (the module keeps one scan's output per descriptor); each costs the module a `scan_buf_cap` buffer once used. Another `mode=1` reader of the same process (yt's own daemon targeting it) clears the bits this reads: do not run both on one process. Stats: `yt_scan=ms (N calls, P pages, cut=C)` on the `syscall ms` line, P counting every page the requests covered. Cost, measured as root on claudepc (2-CPU x86, Linux 6.8, module built from the yt tree): 1 GiB of 4 KiB pages scanned in requests of 256 / 64 / 16 / 1 MiB cost 8-28 / 13-35 / 34-55 / 457-505 ns per page, i.e. ~110 us per request, most of it the module zeroing its whole `scan_buf_cap` buffer after every scan; a smaller `scan_buf_cap` makes requests cheaper and smaller. On the 150 s workload above: K=4 0 faults, read pass 4.5 / 23 ms, scan 0.50 s in total (`idle` K=4: 2.2 s); K=1 8.8 / 10 ms, scan 0.84 s (`idle` K=1: 9.2 s); all compressed the idle 393216 pages. Ratio-gate backoff is unaffected (a 64 MiB random block: 81920 attempts in 79 ticks, as under `protread`)
- `idle` and `yt` under kernel reclaim: both read the hardware accessed bit, and the kernel's own reclaim clears it too. One forced MGLRU aging pass (`+ memcg node max_gen 1 1` into `/sys/kernel/debug/lru_gen`) right after 16384 pages were touched left both blind: page_idle and yt each saw 0 of them accessed (16384 of 16384 without the pass). An access the kernel ages away is lost to smash, so under heavy reclaim a hot slice can look idle for the cold timeout and be compressed: once in 8 runs of the 150 s workload above (yt K=4, claudepc swapping ~40k pages in and out at the time) 16384 hot pages were, then restored by 16384 shadow faults within 5 s; 0 in the other 7, and 0 in a run with a 2.6 GiB hog forcing steady reclaim. Cheap next to `protread`'s normal 2.7-2.9M monitor and 7.6-16k decompression faults per run, but a box whose kernel reclaims the process's memory will see such bursts with either tracker
- `SMASH_STORE_DRAIN_PCT=N` (default 50, 0-100; 0 = never): blob store compaction, the only way the store gets back the bytes of freed blobs. Stores only ever bump into a region; a freed blob leaves a hole nothing reuses. A 16 MiB store region that has used at least 1 MiB and holds less than N % of it in live blobs is marked draining (each tick, before Phase 1): nothing new is stored in it, and Phase 1 moves the live blobs of every compressed or shadow page it finds there (copy into the same store's survivor region, repoint the page under its page lock, release the old blob), so the region empties and is decommitted. The regions a shard bumps into drain too and are replaced by an emptied region or a new one. So a store holds at most about 100/N x its live bytes, plus the regions still filling. **0 is for diagnosis only**: with it no hole is ever reclaimed, and a churning store's held memory grows until every blob in a region is gone. History: a 128-core application's store went from 1.7/5.2 to 1.6/15.7 GiB (live/held) in three hours when holes were reused only by blobs that fit them and nothing was moved. Measured, 1 GiB of mixed-size blobs with 2000 random pages read back and recompressed every 0.5 s for 180 s: held 527 -> 1179 MiB and still growing without compaction, flat at 394-475 MiB with it (live ~330 MiB), rss 1486 -> 781 MiB, process CPU 304 -> 201 s. Then the free list was dropped (stores only bump) and moved blobs given their own region: on the same workload for 150 s user CPU 90 -> 29 s, total CPU about -20 % (counted per thread, kernel time unchanged), held about 10 % higher (421-476 vs 449-548 MiB), ~2 GiB moved instead of ~0.9; store lock held 14 -> 1.3 us on average; with 8 reader threads the slowest release waited 26 -> 2 ms for the lock and the p99 faulted read fell 1.6-1.8 -> 0.74-0.87 ms. See `CompressStore` in `src/compress/compress_store.h`.
- `SMASH_YT_DEVICE=path` (default `/dev/youngtrace/scanner`): the youngtrace device `SMASH_WRITE_TRACK=yt` opens
- `SMASH_YT_REQ_PAGES=N`: tests only — cap a yt request at N pages, so request edges fall inside huge pages
- `SMASH_IDLE_SCAN_TICKS=K` (default 4, 1-64): with `SMASH_WRITE_TRACK=idle` (16 MiB slices) or `yt` (64 MiB slices), each slice is scanned every K ticks (a 1/K share per tick) and credited the K ticks' nominal time. Every scan clears the accessed bits the CPU then sets again on the next touch: K=1 made the read pass above 9.7 ms and used 22.4 s of system time. A scan costs 380-440 ns per resident uncompressed page in a running process (14 + 80 + 81 ns with ideally contiguous PFNs)
- `SMASH_PROTECT_CHUNK_PAGES=N`: pages per Phase 3 arming run, and so per `mprotect` (default 256, clamped to [1, 256]). Each contiguous stretch of a run is armed with one call
- `SMASH_STATS_SIGNAL=1`'s first line, `[smash stats]`, gives page counts by state from a scan at dump time (`active= monitor= compressing= compressed= shadow= empty=`: current; `compressed=` is pages out of RAM, `compressed + shadow` the pages holding a blob) and, at its end, `rss=` (the process's resident set in MiB: `/proc/self/statm`, read with raw syscalls in the signal handler; `phys_footprint` on macOS) and `blob=live/held MiB(N regions, D draining, M MiB moved)`: the bytes of compressed blobs stored now, and the bytes below the bump pointer of every blob region (live plus the holes freed blobs left: what the store keeps resident), summed over the shared store and every NUMA node group's, read without locks; then the regions being emptied by compaction now, and the blob bytes compaction has moved since start (see `SMASH_STORE_DRAIN_PCT`). The saving at a dump is `compressed` x 4 KiB minus `held`. `zero=` on the same line is cumulative (all-zero pages compressed since start), as is everything on the pipeline line; `zero_now=` is current: of `compressed=`, the pages stored as the all-zero sentinel (no blob), from the same scan. `codec=lz4|zstd1` is the fast-tier codec in use (`SMASH_CODEC`), and `cold_arenas=` the (arena, size class) buckets switched to their cold slab (`SMASH_COLD_ARENA_FEEDBACK`; 0 when it is off). Added because a 128-core application's dumps gave 26M compressed pages but no way to read the RSS or the blob cost from the log
- `SMASH_STATS_SIGNAL=1` also prints a `[smash pipeline]` line after the stats line: compressor ticks and the last/slowest tick in ms, ticks deferred by the VMA guard; phase 1 page-ticks accessed vs idle; phase 2 pages at the cold floor, escalated to read watching, eligible, routed to a node group, skipped by a budget/profile hint; compression attempts, blobs stored, ratio-gate failures, ROI declines (`roi_skip=`, before any codec runs); shadow pages checked, released, found changed, and reclaim stops at the VMA cap; faults on monitored, shadow, compressed and ACTIVE pages; the wall time of each phase of the last tick (`phase_ms=1/2/3/4`) and the slowest so far (`max=`); Phase 1's minor faults on compressor threads, slowest single range, the worker count of the last tick and the CPU-pressure cap last computed (`cap=`, 0 = none); Phase 3 pages armed and `mprotect` calls; Phase 2 `mprotect` calls; re-arm backoff (`rearm hot=` write faults on watched pages within a tick of arming, `waits=` page-ticks left unarmed); write-fault locality (`group nbr_active=`: summed over write faults, other pages of the faulting page's aligned 16-page group already ACTIVE) and `restored=` (neighbours a group restore made writable); phase 5 (node groups draining their queues, where most compression runs on a multi-node host) last and slowest wall time (`p5 ms= max=`). Cumulative since start. A second line, `[smash phase time] thread ms usr/sys/runq/blocked: p1=… p5=…`, splits each phase's thread time, summed over every thread that ran it: user CPU, kernel CPU (`getrusage(RUSAGE_THREAD)`), runnable but waiting for a CPU (`/proc/thread-self/schedstat`), and the wall time left over (blocked on a lock such as `mmap_lock`, a futex or I/O). The same line ends with `tick ms total= phases=` (all tick time and the part spent in phases 1-5, cumulative) and the coordinator's cumulative ms in each step outside the phases: `efficiency` (budget recompute), `vma_sync` (re-reading `/proc/self/maps`), `bitmap`, `node_chunks`, `adapt` (worker count), `dict` (dictionary training), `sweep` (deferred madvise). Added when a 97 s tick showed phases summing to ~22 s (it was a dump mixing two ticks: the next run had 99% of tick time in the phases). Then `syscall ms memread= (N calls) p2_mprotect= p3_mprotect= p4_release=`: wall ms inside phase 2's `/proc/self/mem` page snapshots (two per page with FixAv: snapshot and verify), its `mprotect` calls, phase 3's arming, and phase 4's release and look-ahead arming — which calls the `blocked` column waits in. Then a `[smash faults] handler us:` line: per fault kind (`compressed` = decompression, `shadow`, `monitor` = first write to a watched page, `active`), the count, mean, p50/p99/p99.9 (upper bound of the log2 bucket each falls in) and worst time inside smash's fault handler, from entry — waiting for the page lock included — to return; the kernel's signal delivery around it is not. Its counts equal the pipeline line's `faults` counters. On an 8-vCPU x86 VM: decompression avg 23-32 us (p99 < 64 us), monitor avg 2 us. Sampled only with `SMASH_STATS_SIGNAL=1`. Checked on 8 CPUs with 16 busy-loop hogs: phase 5's runq went from 167 to 3284 ms. Added to find where pages stop when an application kept 115 GiB watched and compressed nothing
- `SMASH_NO_SIGACTION_WRAP=1`: the application's `sigaction()`/`signal()` for SIGSEGV/SIGBUS go to libc untouched again, so its handler replaces smash's until the next compressor tick re-claims it (the behaviour before the interposition; for measuring it)
- `SMASH_SIGTRACE=1`: one line per fault smash does not resolve and passes on (`[smash sig] ... chain_kind=...`), with what smash thinks the address is (arena page and its state, or not smash's). The record to ask for when an application with its own SIGSEGV handler crashes: that handler runs instead of smash's `[smash FATAL]` line
- `SMASH_DUMP_CRASH_BT=1`: backtrace before the process dies, only when the fault chains to the default action (no application handler)
- `SMASH_WRITE_TRACK_SIMULATE_OLD_KERNEL=1`: tests only — the soft-dirty and userfaultfd probes report unavailable, as on arm64 before 6.7
- `SMASH_CPU_PRESSURE_CAP=0`: disable the compressor's CPU-pressure cap (workers then follow the Little's-law estimate alone, up to `kMaxCompressorWorkers`). The cap is `max(floor, nproc - round(1-min loadavg))`, floor `clamp(nproc/16, 2, kMaxCompressorWorkers)` on >= 4 CPUs, else 1. It used to subtract every thread of the process, so a process with nproc threads or more always got one worker (`test_worker_cap`).
- `SMASH_TEST_TICK_DELAY_MS=N`: test-only; the compressor sleeps N ms at the end of every tick, to reproduce the multi-minute ticks of a large contended host (`test_slow_tick`). Cold counts, shadow ages and re-arm waits advance by the tick's length in nominal `kCompressIntervalMs` ticks (at least 1, cold counts saturating at 255 and stopping at the cold floor so the read-watch tick still happens), so `SMASH_COLD_TIMEOUT_SEC` and `SMASH_DEFERRED_RECLAIM_DELAY` mean seconds even when ticks do not.
- `SMASH_TEST_TICK_MS=N`: test-only; a tick starts every N ms instead of every second. Every tick still counts as at least one nominal tick, so here, unlike with slow ticks, the cold timeout, shadow delay and re-arm waits are counted in ticks: at N=50 the whole pipeline runs 20x faster (`SMASH_COLD_TIMEOUT_SEC=1` is about 50 ms). `integrity_stress_test`.
- `SMASH_TEST_WORKERS=N`: test-only; exactly N default compressor workers every tick (at most `kMaxCompressorWorkers`), whatever λ/μ and the CPU-pressure cap say, so worker range boundaries exist on a small heap and a 2-CPU host. `integrity_stress_test`.
- `SMASH_TEST_JITTER_US=N`: test-only; one `protectPages`/`decommitPages` call in four first sleeps a random 0..N us (at most 100000). Widens check-then-syscall race windows. Off costs one relaxed load per call. `integrity_stress_test`.
- `SMASH_TEST_NO_MEM_SNAPSHOT=1`: test-only; deferred mode never snapshots a page through `/proc/self/mem`, so it takes the fallback (page made PROT_RW, then copied) and shadow pages stay writable. Phase B's content check is then the only guard against a write during the shadow window (`test_shadow_free_slots_rw`).
- `SMASH_REARM_BACKOFF_MAX=N` (default 6, 0 = off, max 7): under page-protection write tracking, a page written within a tick of being armed waits 2^exp ticks before Phase 3 arms it again, exp rising by one per such fault up to N (6 = 64 ticks) and cleared by a fault after 8 quiet ticks. Bounds each hot page to one write fault (SIGSEGV + `mprotect`) per 2^N ticks instead of one per tick; costs a page that turns cold after being hot up to 2^N ticks more before it is compressed. 2 bytes per page of metadata. See performance.md, "Hot pages were re-armed every tick".
- `SMASH_RESTORE_GRANULE_PAGES=N` (default 1 = off; power of two up to 512): under page-protection write tracking, a write fault on a watched page makes its whole aligned N-page group writable, one `mprotect` per contiguous stretch of ACTIVE / ACTIVE_MONITORING pages (compressed, shadow and free neighbours are never touched; neighbours are taken with `tryLock` only). Writes that cluster then cost one fault per group: 1.05 -> 0.062 faults per page per tick for a sequential writer at N=16. Neighbours made writable are re-armed by the next Phase 3 (they do not inherit the faulting page's backoff) and their cold count is frozen for that tick (neither counted idle nor reset). Scattered writes gain nothing and pay extra re-arming: a random-write stress had 14.8k -> 12.4k faults for 185k neighbours restored. Decide from `group nbr_active=` / `faults monitor=` with it off: the average number of already-written pages in a faulting page's 16-page group.
- `SMASH_PREFETCH_WINDOW=N` (default 2 = `kPrefetchWindow`; 0 = off; capped at 64): compressed neighbours a fault restores on each side of the faulting page, within the same block. Each costs a decompress and two syscalls on the faulting thread, one page at a time: random-access faults measured 53 µs at 2 against 15 µs at 0 (8-CPU VM). Sequential access gains from it; random access pays for it. Not used under `SMASH_WATCH_GROUP_PAGES` > 1, where a fault restores its whole group. Until 2026-10-15 a build option only (`-DSMASH_PREFETCH_WINDOW=N`, which still sets the default). Anything that is not a non-negative number keeps the default with a `[smash WARN]`
- `SMASH_COLD_ARENA_FEEDBACK=1|0` (default off): full mode only (it routes small allocations). Each (call-site arena, size class) gets a second, cold slab; once `SMASH_COLD_ARENA_THRESHOLD` (default 8) of a bucket's pages have been compressed, its later allocations come from the cold slab, so objects that go cold stop sharing pages with ones that stay hot. The stats line's `cold_arenas=` counts the buckets switched. The cold slabs share the 128-entry slab table, so with feedback on the hot arenas are capped at 64 (`SMASH_NUM_ARENAS=128` gives 64). Slots a thread cache already holds from the hot slab are still handed out first. Until 2026-10-15 a build option only (`-DSMASH_COLD_ARENA_FEEDBACK=ON`, which still sets the default; the build doubled the slab table instead of capping)
- `SMASH_WATCH_GROUP_PAGES=G` (default 1 = off; power of two up to 64): coarse watching. An aligned group of G pages is idle only when all of its pages are — Phase 1 gives every uncompressed page of a group the group's lowest cold count — so a group is armed, escalated, compressed and released in the same tick, a write fault restores the whole group (implies `SMASH_RESTORE_GRANULE_PAGES` >= G), a fault on a compressed page prefetches the rest of its group (across a block boundary too), and a group is not armed while one of its pages waits out a re-arm backoff. Pages are still compressed 4 KiB at a time, so fault latency is unchanged; the cost is that one hot page keeps its whole group uncompressed. 64 MiB written in random page order under `SMASH_SOFTDIRTY=0`: at most 9445 mappings and 40880 protection calls per page, 678 and 11141 with G=16 (`test_watch_group`). Worker ranges and node-group slices are cut on 64-page boundaries when it is on.
- `SMASH_LARGE_STATS=0`: pages inside large blocks find no span for the compressor's (arena, bucket) statistics, as before 2026-10-09 (then: no ratio samples or hints for them, and the ROI gate always compresses). Default on.
- `SMASH_NO_MONITOR=1`: Disable Phase 3 (PROT_READ access tracking) entirely. Trades cold-detection accuracy for compatibility with code paths that synchronously check page protection
- `SMASH_VM_GIB=N`: Size of the compressible arena, default 16, ceiling 1 TiB (`kVmMaxBytes`). The arena is a PROT_NONE `MAP_NORESERVE` reservation and its per-page metadata is demand-paged, so an unused arena costs address space, not memory (measured: 16, 64 and 1024 GiB all start at 23.3 MB RSS). If the reservation fails — a 39-bit-VA arm64 kernel, `ulimit -v` — `VmRegion::init` halves the request down to 256 MiB and says so, instead of silently running without compression as it used to (measured: with a 48 GiB address-space limit, `SMASH_VM_GIB=1024` gets a 32 GiB arena and compresses; before, compression was off). The old 64 GiB ceiling was an estimate of metadata cost, not a limit; page indices are 32-bit, so the hard bound is 16 TiB
- `SMASH_NO_DRAIN_WAIT=1`: an allocation that finds no free run gives up immediately instead of waiting for runs that are freed but still queued for decommit (the pre-fix behaviour). For measuring what that wait is worth on a given machine — an absolute fallback rate is not portable across core counts
- `SMASH_NO_RECLAIM_WAIT=1`: every thread that runs the arena out runs its own empty-span reclaim pass concurrently and treats a slab another pass holds as empty, instead of waiting for that pass (the pre-fix behaviour). For measuring the wait; see `test_arena_reclaim_concurrent` in [tests.md](tests.md).
- `SMASH_RUN_CACHE_MIB=N`: per-CPU cache of freed large runs, N MiB per CPU (256 shards, one per CPU up to 256 CPUs; 8 runs each; runs over 64 MiB never cached); 0/unset = off (default). A block freed warm (no page compressed) is parked and reused by the next same-size allocation on that CPU and node, skipping the node arena's lock, the free map, the decommit queue, mprotect/madvise and zero-fill faults. Costs up to (CPUs in use) x N MiB of resident memory while runs are parked — 128 CPUs at N=32 is 4 GiB. See [design-run-cache.md](design-run-cache.md)
- `SMASH_RUN_CACHE_AGE_MS=N`: age after which the decommit thread returns a cached run to the arena (default 50)
- `SMASH_SUBARENAS=1`: per-CPU sub-arenas for the NUMA node arenas (`malloc_numa`) and for plain `malloc`'s large blocks (the shared arena, unbound chunks), off by default ([design-subarenas.md](design-subarenas.md)). Each node's chunks are owned by sub-arenas with their own lock; a block freed warm goes back to its chunk's sub-arena as **dirty** — resident, no syscall — and any later allocation that fits reuses it without zero-fill faults. Compressed frees still go through the decommit queue and come back **clean**. Turns the run cache off. Costs resident memory up to `SMASH_DIRTY_MAX_MIB` per sub-arena for up to `SMASH_DIRTY_DECAY_MS`; `smash_subarena_info()` reports the dirty bytes
- `SMASH_SUBARENAS_PER_NODE=N`: sub-arenas per node, 1..64 (default: one per CPU of the node, from sysfs). A thread uses its CPU's rank within the node; a CPU of another node maps by `cpu % N`. The shared arena's set gets a slice of N per node with CPUs, scaled down to 64 in total (128 CPUs over 4 nodes: 16 per node), so CPUs of one node share sub-arenas with each other only
- `SMASH_DIRTY_DECAY_MS=N`: age at which the node's decommit thread (sweeping every 50 ms, trylock only) returns a dirty run to the OS (default 1000; 0 = next sweep)
- `SMASH_PURGE_EPOCH_MS=N`: how often each set's purger sweeps for dirty runs past the decay time (default 50). A free over the cap never waits for it. The sub-arena tests set 200 so a purge that did wait would miss their 20 ms window
- `SMASH_DIRTY_MAX_MIB=N`: dirty MiB per sub-arena before the oldest are purged early, splitting the run that crosses the cap (default 256). A free that crosses it wakes the purger at once (after dropping the sub-arena's lock), and an urgent purge that still leaves a sub-arena over the cap is retried every 1 ms, so the bound holds within milliseconds, not only at the 50 ms sweep
- `SMASH_ALIGN_SLOT_SEARCH=1`: Keep an aligned small allocation in its natural size class and search that class's bitmap for an aligned slot, instead of promoting it to a class that is a multiple of the alignment. **Off by default and usually a loss** — the stranded slots make it up to 7× worse, and call-site arena routing keeps plain allocations from filling them. See "Aligned small allocations come from the slab" in [allocation-paths.md](allocation-paths.md)
- `SMASH_ALIGN_SLAB=0`: Restore the old aligned-allocation routing, where any alignment above 16 B goes to `LargeAlloc` and costs a whole page per object. Default ON (slab-served); see "Aligned small allocations come from the slab" in [allocation-paths.md](allocation-paths.md)
- `SMASH_MID_BINS=1`: Serve the (16 KiB, 1 MiB) band from size-binned chunks in the compressible arena instead of one direct `mmap` each. Off by default: it trades ~10% of the requested bytes to size-class rounding for compressibility and much cheaper churn, which only pays for blocks that go cold. See "Mid-size bins" in [allocation-paths.md](allocation-paths.md)
- `SMASH_THP=1`: `madvise(MADV_HUGEPAGE)` the arena. Off by default: it keeps a dense hot set on huge pages (TLB coverage) while the cold set still compresses, but inflates RSS 22× on a sparse touch pattern. See "Hugepages and THP" in [allocation-paths.md](allocation-paths.md)
- `SMASH_LARGE_ALLOC_VM_THRESHOLD=N`: Bytes at or above which a large allocation is placed in the compressible VmRegion instead of a direct mapping (default `kLargeAllocVmThreshold` = 1 MiB; rounded up to a page). **This decides what can be compressed at all** — a block below it is never walked by the compressor and stays resident however cold it gets. Lower it for a workload whose footprint is mid-sized blocks; see "Which allocation sizes are actually compressed" in [allocation-paths.md](allocation-paths.md)
- `SMASH_COLD_TIMEOUT_SEC=N`: Override cold timeout at runtime, in seconds (`SMASH_COLD_TICKS=N`, in ticks, when it is unset). At most **254** (`kMaxColdTicks`): a page's idle count is one byte that stops at 255 and a page is compressed only above the timeout, so 255 or more used to compress nothing, silently. Larger values are clamped to 254 with a `[smash WARN]` (switch compression off with `SMASH_NO_COMPRESSOR=1`, not a huge timeout); text that is not a positive number keeps the default with a warning. Parsed once in `config.h` (`parseColdTicks`) for both the compressor and the cooling-close default. `test_compression`'s `testColdTimeoutParse`, `test_compression_cold_max`, `test_cold_timeout_env`.
- `SMASH_DOUBLE_FREE=off|warn|abort`: Double-free detection, **default `off`**. `warn` reports to stderr (rate-limited, via `safe_snprintf` + `write(2)` — never `fprintf`, which can call malloc and reenter) and drops the second free; `abort` reports then traps. A double free is UB, so this is a debugging aid rather than a safety guarantee: it is not a promise that a detected double free was harmless, only that this one was dropped. No measurable cost when enabled (see `test_double_free_full`)
- `SMASH_NO_EXIT_GUARD=1`: Disable the process-exit guard, so smash's background threads keep the process alive after the application's last thread exits (the pre-fix behaviour — see "Process exit after `pthread_exit()` from main" in [defect-history.md](defect-history.md)). Escape hatch for an application that genuinely relies on a library's threads outliving its own
- `SMASH_COOLING_CLOSE_TICKS=N`: Cooling-page closing threshold (default `getColdTicks()/2`; `0` disables). Slab allocation prefers warm/EMPTY pages over pages whose cold streak ≥ N, and redirects to a decommitted empty span (never a new one) when the front span has only cooling/compressed free slots. Allocator-induced re-heats are counted in the `reheat=` field of the SIGUSR2 stats line (`SMASH_STATS_SIGNAL=1`); the telemetry threshold stays at the default even when closing is disabled, so A/B runs can measure prevented re-heats. Note: objects recycled through the thread cache bypass slab placement entirely — the app's writes into recycled objects re-heat their pages regardless of this policy
- `SMASH_RECOMPRESS_BACKOFF=0|1` (default 1): recompression-thrash back-off. A page faulted back from COMPRESSED must stay idle `floor << (count + bias)` ticks before it is compressed again (shift at most 6, at most 200 ticks); `bias` is 1 for every page of an (arena, size class) bucket while more of the bucket's compressed pages came back (restored by an access) than stayed (compressed for 8 ticks, counted once per compression); both counts are halved once they sum to `kBucketBiasWindow` (1024, `-DSMASH_RECOMPRESS_BUCKET_WINDOW=N`). Until 2026-10-16 it never wore off, and restores of a large block's pages other than its first did not count. A restore the allocator caused by handing out a block on the page counts for neither (`alloc_reopen=` in the pipeline line). The count decays one step per 8 ticks the page spends compressed. Until 2026-10-15 it also decayed while the page waited, which cut every wait to about 8 ticks. Since the cap is 200 ticks, the back-off can at most double a cold timeout of 100 s and does nothing above 200 s. `test_compression`'s `testRecompressBackoff` and `testAllocReopen`, `test_thrash_backoff(_large)`, `test_alloc_reopen`.
- `SMASH_CODEC=lz4|zstd` (`zstd1` also accepted): the fast-tier codec, chosen at startup; unset, zstd-1. Anything else keeps the default with a `[smash WARN]`. The stats line reports it as `codec=`. Before 2026-10-15 the codec was a build option only (`-DSMASH_USE_LZ4=ON`, now removed; CMake warns if it is passed): **`SMASH_USE_LZ4` was never an environment variable**, and setting it did nothing (an application set it for months, and `test_large_bucket_decline` was registered with it). Measured on 64 MiB of text-like pages: 32 MiB of blobs with LZ4, 18 MiB with zstd-1. Blobs carry their codec, so a fault decompresses each page with the codec it was stored with
- `SMASH_VERY_COLD_TICKS=N`: Override deep-tier cold-tick threshold (ROI model). `9999` disables the deep tier entirely (fast tier only). Until 2026-10-15 `9999` removed every zstd profile, the zstd-1 fast tier included, so nothing was compressed at all.
- `SMASH_ROI_THRESHOLD=N`: Override ROI cutoff (default 1024)
- `SMASH_FAST_COMP_MBS_HI/LO`, `SMASH_FAST_DECOMP_MBS_HI/LO`: Override fast-tier calibration
- `SMASH_DEEP_COMP_MBS_HI/LO`, `SMASH_DEEP_DECOMP_MBS_HI/LO`: Override deep-tier calibration
- `SMASH_CALIBRATE=always|never`: Force/skip startup calibration
- `SMASH_CALIBRATION_FILE=path`: Cache and reload calibration. The file records the codec its fast-tier figures were measured with (`"fast_codec"`); a file for another codec (an untagged one counts as zstd-1's) is ignored, re-measured and rewritten. Until 2026-10-15 setting this hung every process at startup: `fopen()` inside the heap's constructor waited for the heap
- `SMASH_NUMA_COMPRESSOR=0`: Disable the per-node compressor groups. `malloc_numa` pages are then compressed by the default workers into the shared store
- `SMASH_NUMA_WORKERS=N`: Threads per node compressor group (default `kCompressorWorkers`, capped by the node's CPU count and 8)
